# AAFR Setup Guide

This document provides practical, step-by-step guidance for setting up the software environments used with the AAFR analysis pipeline described in:

**Co-occurrence of rapid motion and close proximity as a proxy for Drosophila male aggression**

The workflow uses two separate software environments:

1. a **Docker-based Python environment** for video preprocessing, frame-to-frame image-change analysis (ΔI), distance processing, AAFR calculation, and statistical analysis; and
2. a **DeepLabCut environment** for markerless tracking of the two flies.

The versions listed below describe the environment used for the study and subsequently checked during manuscript revision. They are not necessarily the only versions that can run the pipeline.

For the analysis procedure itself, parameter definitions, and recalibration guidance, see [`README.md`](README.md).

---

## Using an AI assistant during setup

Software installation can be difficult because the exact procedure depends on the operating system, hardware, GPU driver, CUDA installation, and software already present on the machine.

An AI assistant can be useful during setup. A practical approach is to provide the AI with this entire `SETUP.md`, describe your operating system and hardware, and ask it to guide you through the installation **one step at a time**.

When an error occurs, provide the complete command and the complete error message. This is usually much more useful than summarizing the problem.

For example, you can ask:

> I want to install the AAFR analysis environment described in this SETUP.md. I am using Ubuntu 22.04 with an NVIDIA GPU. Please guide me through the setup one step at a time. After each step, wait for me to show you the output before continuing.

AI-generated instructions should still be checked before execution, especially commands involving administrator privileges (`sudo`), system packages, GPU drivers, file deletion, disk formatting, or environment modification. The authors cannot guarantee that instructions generated by an AI system will work on every computer.

## 1. Overview of the software architecture

The AAFR workflow separates tracking from the rest of the analysis.

```text
Video
  |
  +--> AAFR Docker environment
  |      - video preprocessing
  |      - frame extraction
  |      - binary foreground generation
  |      - ΔI calculation
  |      - distance-data processing
  |      - AAFR calculation
  |      - statistical analysis
  |
  +--> DeepLabCut environment
         - multi-animal tracking
         - thoracic coordinates for both flies
```

DeepLabCut was run separately from the AAFR Docker container in the study.

A GPU is strongly recommended for DeepLabCut. The AAFR calculations outside DeepLabCut do not require a GPU.

---

## 2. General requirements

A Linux workstation is recommended.

The study was performed on Ubuntu 22.04 systems. Other systems may work, but the instructions below were developed from the Linux workflow.

You will need:

- Git
- Docker
- sufficient disk space for videos and extracted frames
- Conda (Anaconda or Miniconda) for the DeepLabCut environment
- an NVIDIA GPU and suitable NVIDIA drivers for practical DeepLabCut use

Video frame extraction can generate a very large number of image files. Check available disk space before processing an entire experiment.

Clone the repository and enter its root directory:

```bash
git clone https://github.com/Takayuki-Kuraishi/kuraishi-aafr-paper.git
cd kuraishi-aafr-paper
```

Confirm that the expected files are present:

```bash
ls
```

You should see `README.md`, `docker/`, and `scripts/`, among other files.

# Part I. AAFR analysis environment

## 4. Install Docker

Install Docker Engine using the official Docker documentation for your operating system:

https://docs.docker.com/engine/install/

On Linux, confirm that Docker is available:

```bash
docker --version
```

A basic installation test is:

```bash
docker run hello-world
```

If Docker requires `sudo` on your system, either use `sudo` where appropriate or configure Docker according to your local system-administration policy.

---

## 5. Build the AAFR Docker image

The repository contains a Dockerfile at:

```text
docker/Dockerfile
```

From the repository root, build the image:

```bash
docker build -t aafr-paper-env docker/
```

The Docker environment used for the study contains:

- Python 3.11
- NumPy 1.26.4
- pandas 2.2.2
- SciPy 1.15.3
- Matplotlib 3.9.0
- OpenCV 4.8.1.78

The package versions are pinned in the Dockerfile.

---

## 6. Start the AAFR container

For a simple setup, mount the repository directory as `/work`:

```bash
docker run -d \
    --name aafr-paper-env \
    --restart unless-stopped \
    -v "$PWD":/work \
    -w /work \
    aafr-paper-env
```

Confirm that the container is running:

```bash
docker ps
```

Check Python:

```bash
docker exec aafr-paper-env python --version
```

Check the principal packages:

```bash
docker exec aafr-paper-env python -c \
'import numpy, pandas, scipy, cv2; print("AAFR analysis environment OK")'
```

If the final line is:

```text
AAFR analysis environment OK
```

the basic analysis environment is working.

---

## 7. Avoiding root-owned output files

By default, commands executed inside a Docker container may create files owned by `root` on the host system.

When a command will create or modify files in a mounted host directory, it is useful on Linux to execute it with the host user's UID and GID:

```bash
docker exec \
    --user "$(id -u):$(id -g)" \
    aafr-paper-env \
    <COMMAND>
```

For example:

```bash
docker exec \
    --user "$(id -u):$(id -g)" \
    aafr-paper-env \
    python scripts/compute_aafr.py --help
```

This is not required on every system, but it can prevent later permission problems.

# Part II. DeepLabCut tracking environment

## 8. Why DeepLabCut is separate

AAFR requires the distance between the two flies in each frame.

In the study, the thoracic center of each fly was tracked using DeepLabCut in multi-animal mode. DeepLabCut was used for coordinate estimation, not for aggression classification.

The downstream AAFR code therefore requires tracking coordinates, but it does not require DeepLabCut itself to run inside the Docker container.

Other reliable tracking methods could in principle provide the required coordinates, but the scripts in this repository were developed and tested with the DeepLabCut output format used in the study.

## 10. Create a Conda environment for DeepLabCut 2.3.7

Install Anaconda or Miniconda if Conda is not already available.

Confirm the installation:

```bash
conda --version
```

Create a dedicated environment:

```bash
conda create -n DEEPLABCUT2-3-7 \
    -c conda-forge \
    python=3.10 \
    pip \
    ipython \
    jupyter \
    "notebook<7.0.0" \
    ffmpeg \
    "pytables=3.8.0"
```

Activate it:

```bash
conda activate DEEPLABCUT2-3-7
```

Install the DeepLabCut version used in the study:

```bash
python -m pip install "deeplabcut[gui,tf]==2.3.7"
```

The working study environment contained TensorFlow 2.10.0 and Keras 2.10.0. Check the versions produced by your installation before proceeding.

If necessary, they can be installed explicitly:

```bash
python -m pip install "tensorflow==2.10.0" "keras==2.10.0"
```

Because package availability and dependency resolution can change over time, do not assume that an installation succeeded merely because the installation command completed. Verify the environment as described below.

With the environment activated:

```bash
conda activate DEEPLABCUT2-3-7
```

For the study environment, the expected core versions were:


Check whether TensorFlow can see an NVIDIA GPU:


```bash

```

# Part III. Tracking configuration

## 13. Use multi-animal tracking

The downstream distance-processing workflow in this repository was developed with **DeepLabCut multi-animal tracking**.

The study tracked one landmark on each animal:

```text
thoracic center
```

The inter-fly distance was calculated from the two thoracic coordinates.

### Important note on single-animal output

Do not assume that single-animal and multi-animal DeepLabCut CSV files are interchangeable.

During development of this pipeline, single-animal tracking output produced alignment problems and zero-distance values in the downstream distance calculation. The published workflow therefore uses the multi-animal output format used in the study.

If a different DeepLabCut configuration is used, inspect and validate the resulting CSV structure before applying the distance-processing scripts.

---

## 14. Training a new tracking model

A new model does **not** need to be trained for every experiment.

If an existing model performs well on new recordings, it can be reused.

When training a new model, the study used manually labeled frames in which the thoracic center of each fly was identified. The exact number of labeled frames and training iterations used in the study describe that particular model and should not be treated as universal requirements.

The important criterion is tracking quality on the recordings to be analyzed.

Changes that may reduce tracking performance include:

- substantially different illumination
- different camera geometry
- different magnification
- different arena appearance
- markedly different animal appearance
- substantially different behavioral or imaging conditions

When such changes occur, test the existing model first. Add labeled frames or retrain only if tracking is inadequate.

---

## 15. Test the tracking model before batch analysis

Do not begin by processing an entire experiment.

First select a small number of representative videos, including difficult examples if possible, and analyze those.

Evaluate tracking in two ways:

1. inspect quantitative tracking completeness; and
2. inspect labeled videos visually.

A low missing-coordinate rate does not by itself prove that the landmarks were assigned correctly. Conversely, a poor numerical result may sometimes reflect an empty arena or another problem with the input rather than failure of the model itself.

Whenever possible, confirm that both thoracic landmarks are visibly placed on the two flies in representative frames.

---

## 16. Avoid empty arenas or wells in tracking batches

Check that the videos selected for tracking actually contain the intended animals.

During development, empty wells caused problems in batch DeepLabCut processing.

It is therefore useful to verify occupancy before launching a large batch.

---

## 17. Analyze videos with the DeepLabCut GUI

The routine workflow used for the study was:

1. activate the DeepLabCut environment;
2. start DeepLabCut;
3. load the tracking project;
4. open **Analyze videos**;
5. select the videos to analyze;
6. use the multi-animal identity-tracking workflow;
7. save the tracking results as CSV.

For the configuration used in the study, the GUI options included:

- **Assemble with ID only**
- **Save results as csv**

The CSV output is required by the downstream distance-processing workflow in this repository.

After analysis, verify that the expected output files actually exist. Do not rely only on a completion message from the software.

Creating labeled videos for a subset of recordings is strongly recommended because it provides a direct visual check of tracking quality.

---

## 18. Optional command-line DeepLabCut operation

DeepLabCut also provides a Python API.

A typical structure is:

```python
import deeplabcut

config_path = "/path/to/project/config.yaml"
video_path = "/path/to/video.avi"

deeplabcut.analyze_videos(
    config_path,
    [video_path],
    videotype=".avi",
    auto_track=True,
    save_as_csv=True,
)
```

Optional visualization functions include:

```python
deeplabcut.plot_trajectories(
    config_path,
    [video_path],
    videotype=".avi",
)
```

and:

```python
deeplabcut.create_labeled_video(
    config_path,
    [video_path],
)
```

The exact API and available arguments may differ among DeepLabCut versions.

For the study, the GUI workflow was used routinely and should be considered the reference workflow for DeepLabCut 2.3.7 in this repository.

# Part IV. Connecting DeepLabCut output to AAFR

## 19. Check the tracking CSV before distance calculation

The distance-processing scripts were developed and tested with the multi-animal CSV structure produced by the DeepLabCut configuration used in the study.

Before processing a new type of DeepLabCut output, inspect the first several lines:

```bash
head -n 10 your_tracking_file.csv
```

Confirm that the two animals and their thoracic coordinates appear in the expected columns.

DeepLabCut versions and project configurations can differ in CSV layout. If the structure differs, the downstream processing script may need to be adapted and validated.

Do not silently assume that a CSV generated by another tracking configuration has the same column organization.

---

## 20. Process tracking coordinates into distance

The repository contains the distance-processing scripts under:

```text
scripts/pipeline/
```

These convert the two tracked thoracic coordinates into inter-fly distance for each frame.

The distance is calculated as the Euclidean distance:

```text
D_t = sqrt((x1 - x2)^2 + (y1 - y2)^2)
```

See `README.md` for the exact pipeline commands and the relationship between pixel distance and physical distance.

# Part V. Minimal end-to-end validation

## 21. Test one recording before processing an experiment

Before launching a large batch, verify the complete workflow using one or a few recordings.

A useful order is:

1. prepare or crop one video;
2. run the image-processing branch and calculate ΔI;
3. track both flies with DeepLabCut;
4. inspect a labeled tracking video;
5. export the DeepLabCut tracking CSV;
6. calculate the inter-fly distance;
7. calculate AAFR;
8. inspect the resulting output files.

Only after this succeeds should the full experiment be processed.

This small-scale test is particularly important after changing:

- computer
- operating system
- DeepLabCut version
- tracking model
- camera
- image resolution
- illumination
- arena geometry
- file naming convention

---

## 22. Analysis parameters are separate from software setup

Successful installation does not establish that the numerical AAFR parameters are appropriate for a new imaging system.

The study used:

- binary foreground threshold: 50 on an 8-bit difference scale
- ΔI threshold: `x_t = 45000`
- distance threshold: `y_t = 70 px`
- spatial calibration: approximately `0.0552 mm/px`
- study-specific tracking QC cutoff: valid-frame ratio ≥ 0.90

These values and their recalibration requirements are described in detail in `README.md`.

In particular, a substantially different imaging setup may require recalibration or verification. Do not change thresholds separately for experimental groups merely because their locomotor activity differs; doing so could remove biological differences that AAFR is intended to measure.

# Part VI. Troubleshooting

## 23. Docker permission errors

### Symptom

Files created by analysis scripts cannot be modified or deleted from the host system.

### Likely cause

They were created as `root` inside the Docker container.

### Prevention

Run file-generating commands using the host UID and GID:

```bash
docker exec \
    --user "$(id -u):$(id -g)" \
    aafr-paper-env \
    <COMMAND>
```

---

## 24. Container already exists

If:

```bash
docker run ...
```

reports that a container named `aafr-paper-env` already exists, inspect it first:

```bash
docker ps -a
```

If it is merely stopped:

```bash
docker start aafr-paper-env
```

Only remove it if you are sure it is no longer needed:

```bash
docker rm -f aafr-paper-env
```

Removing the container does not remove files stored in host directories mounted into it, but always verify your paths before deleting anything.

---

## 25. DeepLabCut imports but no GPU appears

Check:

```bash
nvidia-smi
```

and:

```bash
python -c \
'import tensorflow as tf; print(tf.config.list_physical_devices("GPU"))'
```

GPU configuration problems can involve the NVIDIA driver, CUDA, cuDNN, TensorFlow version, environment variables, or library paths.

Because the correct fix depends strongly on the machine, this is an appropriate situation in which to provide the complete diagnostic output to an experienced system administrator or an AI assistant.

Do not repeatedly install or remove GPU drivers without first determining which component is actually failing.

---

## 26. TensorFlow prints TensorRT warnings

TensorFlow installations may report warnings about missing TensorRT libraries such as `libnvinfer`.

Such a warning alone does not establish whether ordinary DeepLabCut GPU tracking is working.

Check the actual GPU visibility:

```bash
python -c \
'import tensorflow as tf; print(tf.config.list_physical_devices("GPU"))'
```

and test DeepLabCut on a small video.

---

## 27. Tracking quality is poor

Before retraining a model, check:

- whether the video actually contains two flies;
- whether the correct DeepLabCut project was loaded;
- whether the model tracks the thoracic center rather than a different landmark;
- whether image brightness and contrast differ strongly from the training data;
- whether magnification or arena appearance has changed;
- whether the labeled video shows identity swaps or misplaced landmarks.

Test a few representative recordings before deciding that the model must be retrained.

---

## 28. Distance is repeatedly zero or obviously incorrect

First inspect the DeepLabCut CSV itself.

Confirm that:

- two animals are present;
- the expected thoracic coordinates are present for both animals;
- the CSV is from the multi-animal workflow expected by the pipeline;
- the columns have not shifted because of a different DeepLabCut output format.

During development, single-animal output was not interchangeable with the multi-animal format used in this pipeline and produced distance/alignment problems.

---

## 29. Unexpected CSV format

Inspect the header directly:

```bash
head -n 10 your_tracking_file.csv
```

Do not modify the downstream script until you understand the actual column layout.

If the DeepLabCut version or project configuration differs from that used in the study, adapt the parser only after identifying exactly which columns correspond to the two thoracic `x` and `y` coordinates.

---

## 30. Tracking appears complete but may be wrong

Coordinate completeness is only one QC measure.

A tracker can return coordinates in nearly every frame while occasionally assigning them to the wrong location or identity.

For this reason, visually inspect labeled videos for representative recordings, especially when applying an existing model to new experimental conditions.

---

## 31. Very large disk usage

Frame extraction may produce hundreds of thousands or millions of image files.

Before large analyses:

```bash
df -h
```

Check the size of a working directory with:

```bash
du -sh path/to/directory
```

Run a small test first and estimate the disk requirement before processing all recordings.

# Part VII. Applying the workflow to a new laboratory or imaging setup

## 32. What can usually be reused

With the same or sufficiently similar imaging configuration, the following can often be reused after verification:

- the Docker analysis environment;
- the AAFR analysis scripts;
- an existing DeepLabCut tracking model;
- the ΔI threshold;
- the physical distance criterion.

However, reuse should be based on validation, not assumption.

---

## 33. What should be checked when the imaging system changes

If the camera, magnification, resolution, arena, or illumination changes substantially, verify:

- foreground/background separation;
- frame-to-frame ΔI behavior;
- pixel-to-mm calibration;
- the pixel equivalent of the intended physical distance threshold;
- DeepLabCut tracking quality;
- valid-frame ratio.

See the **Parameters and recalibration** section of `README.md`.

# Part VIII. Practical recommendations

## 34. A useful workflow for a new user

For someone setting up the method for the first time, the following order is recommended:

```text
1. Install Git and Docker
2. Clone this repository
3. Build the AAFR Docker image
4. Verify the Docker environment
5. Install Conda
6. Create the DeepLabCut environment
7. Verify DeepLabCut and GPU access
8. Load or create a multi-animal tracking project
9. Test tracking on a small number of videos
10. Inspect labeled videos
11. Verify the DeepLabCut CSV structure
12. Run one recording through the complete AAFR pipeline
13. Only then process the full experiment
```

At each stage, confirm that the expected output exists before moving to the next stage.

---

## 35. General principle

The most reliable way to set up this workflow is not to automate everything immediately.

First establish that each individual stage works:

```text
video
  -> preprocessing
  -> ΔI
  -> tracking
  -> distance
  -> valid-frame QC
  -> AAFR
```

Once the individual steps are understood and verified, batch processing can be introduced.

When something fails, inspect the actual input and output files at the failing stage rather than inferring the problem only from downstream results.

This guide documents the environment and practical workflow used for the AAFR study.
